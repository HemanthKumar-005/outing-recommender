### 2. Context-Aware Dynamic Weather & Temperature Scoring
* In [`services/recommendation-engine/app/scoring.py`](./services/recommendation-engine/app/scoring.py), upgraded `weather_suitability()` from a simplistic rain check into a rich context-aware function:
  * **Extreme Heatwaves ($\ge 38^\circ\text{C}$)**: Strongly penalizes outdoor venues ($0.15$), promotes air-conditioned indoor spaces ($0.95$).
  * **Afternoon Heat ($33\text{--}38^\circ\text{C}$)**: Penalizes outdoor activities in peak afternoon ($0.30$), favors indoor cafes/venues ($0.92$).
  * **Cold Extremes ($< 8^\circ\text{C}$)**: Penalizes outdoor venues ($0.25$), boosts heated/cozy indoor spaces ($0.95$).
  * **Rain**: Penalizes outdoor venues ($0.15$), favors sheltered spaces ($0.95$).
  * **Pleasant Weather & Golden Hour**: Dynamic evening boost for rooftop lounges and scenic spots ($0.95\text{--}1.0$).
* **Test Coverage**: Added test cases in [`services/recommendation-engine/tests/test_cf_and_weather.py`](./services/recommendation-engine/tests/test_cf_and_weather.py).

### 3. Algorithmic TSP Route Solver (2-Opt Heuristic)
* In [`services/itinerary-service/app/planner.py`](./services/itinerary-service/app/planner.py), replaced simple greedy nearest-neighbour sorting with a full **2-Opt Travelling Salesperson Problem (TSP)** heuristic:
  * Added `total_route_distance()` starting from the user's origin.
  * Added `optimize_route_2opt()` to iteratively evaluate pairwise subsegment reversals until no further distance reduction is possible.
  * Eliminates crisscrossing stop sequences for 3–10 stop outings, producing smoother driving/walking itineraries.
* **Test Coverage**: Created [`services/itinerary-service/tests/test_planner.py`](./services/itinerary-service/tests/test_planner.py) covering path calculations, crisscross untangling, and single/empty edge cases (4/4 passing).

### 4. Live Collaborative Filtering (CF) & User Profile Ingestion
* In [`services/recommendation-engine/app/main.py`](./services/recommendation-engine/app/main.py):
  * **User Profile**: Queries `USER_SERVICE_URL/users/{user_id}` and injects the user's actual `budget_min`, `budget_max`, `preferred_categories`, and `ambience_preferences` into feature vectors and context scoring instead of static default ranges.
  * **Collaborative Filtering**: Queries `INTERACTION_SERVICE_URL/interactions` to compute live co-occurrence overlap scores via `scoring.cf_scores()`.
  * **Feature Vector & Fusion**: Passes computed `cf_score` and `cbf_score` into `build_feature_vector()` and `fuse_candidate()`.
  * **Cold-Start Transition**: Automatically activates the `existing_user` profile ($CF=0.18$) once positive user interactions reach $N \ge 3$.
* **Test Coverage**: Added tests in [`services/recommendation-engine/tests/test_cf_and_weather.py`](./services/recommendation-engine/tests/test_cf_and_weather.py).

### 5. Multi-Persona Group Recommendation Endpoint & UI
* **Backend Endpoint**:
  * Added `POST /recommendations/group` and `POST /group` in [`services/recommendation-engine/app/main.py`](./services/recommendation-engine/app/main.py).
  * Accepts `{ user_ids: [1, 2, ...], strategy: "least_misery" | "average" | "borda", lat, lng, radius_km }`.
  * Scores candidate places for each user independently and aggregates scores using `scoring.aggregate_group_scores()`.
  * Returns ranked venues with per-user satisfaction scores and lowest-satisfaction metrics.
* **Frontend Integration**:
  * Added `GroupRecommendation` and `fetchGroupRecommendations` to [`frontend/lib/api.ts`](./frontend/lib/api.ts).
